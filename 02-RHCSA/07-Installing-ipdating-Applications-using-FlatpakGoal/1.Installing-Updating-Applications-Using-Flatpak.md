# Installing and Updating Applications by Using Flatpak

Since Flatpak is new to you, start with this model:

A remote is a software source. An application is installed from a remote, and it may need a shared runtime to run. Flatpak runs applications in a sandbox.

Flatpak is mainly used for desktop applications. It helps applications run across different Linux distributions without relying on each distribution’s system libraries.

## 7.1 Configuring Flatpak for application installation

### Flatpak, runtimes, and sandboxes

A Flatpak application runs in an isolated environment called a sandbox. By default, it has limited access to the host system. Access to resources such as files, the network, devices, and desktop services is controlled by permissions.

Applications use libraries from a runtime rather than depending directly on the host’s system libraries. Several applications can share the same runtime, which saves space. A runtime can also be updated separately from the applications that use it.

### Remotes: where Flatpaks come from

Flatpak repositories are called remotes. RHEL 10 includes a Red Hat remote named `rhel`. Other sources, such as Flathub and Fedora, can also be added. Red Hat does not support applications from third-party remotes.

Flatpak is installed by default in RHEL 10. If it is missing:

```bash
sudo dnf install flatpak
flatpak --version
```

The Red Hat remote may require Red Hat account credentials or a registry service account token. The chapter uses Podman to log in:

```bash
podman login registry.redhat.io
```

List configured remotes:

```bash
flatpak remotes
flatpak remotes -d       # include details such as URL
```

List applications available from a remote:

```bash
flatpak remote-ls rhel --app
```

Add a remote, such as Fedora:

```bash
flatpak remote-add --if-not-exists fedora \
  oci+https://registry.fedoraproject.org
```

By default, this configures the remote system-wide. Use `--user` to make a remote available only to your account:

```bash
flatpak remote-add --if-not-exists --user flathub \
  https://dl.flathub.org/repo/flathub.flatpakrepo
```

Check system-wide and per-user remotes separately:

```bash
flatpak remotes --system
flatpak remotes --user
```

You can disable a remote without uninstalling its applications:

```bash
flatpak remote-modify --disable fedora
flatpak remote-modify --enable fedora
```

Removing a remote with `flatpak remote-delete` can also remove applications and runtimes installed from it. Disable it instead if you want to keep those installed objects.

GNOME Software also manages Flatpak remotes through its Software Repositories screen.

## 7.3 Managing applications from Flatpak

### Application IDs and branches

Flatpak objects—applications and runtimes—have unique IDs, commonly in this form:

```text
org.organization.Application
```

You may be able to use a short name, but a full ID is more precise. An object can also have multiple versions, called branches. A branch may be a version number or a label such as `stable`, `beta`, or `nightly`.

When you need to specify the exact object, use:

```text
ID/architecture/branch
```

For example:

```text
org.mozilla.Thunderbird/x86_64/stable
```

Here, `x86_64` is the architecture and `stable` is the branch.

### Search and install

Search enabled remotes:

```bash
flatpak search thunderbird
```

Search can match the application name, description, ID, or developer-defined keywords.

Install an application:

```bash
flatpak install thunderbird
```

If multiple remotes contain a match, Flatpak asks which one to use. It also shows the required runtime, permissions, and the changes it plans to make. Review these before confirming.

Useful install options:

| Option | Purpose |
| --- | --- |
| `--app` | Install an application |
| `--runtime` | Install a runtime |
| `--system` | Install for all users; the default |
| `--user` | Install only for the current user |
| `--or-update` | Install, or update if already installed |

### List and inspect installed objects

```bash
flatpak list
flatpak info org.mozilla.Thunderbird
```

`flatpak list` shows installed applications and runtimes. `flatpak info` displays details such as the object’s ID, branch, remote, size, and required runtime.

To see the available branches before installing:

```bash
flatpak remote-info rhel com.redhat.Platform
```

If there are multiple branches, specify the desired branch in the identifier.

### Update and mask objects

```bash
flatpak update
flatpak update org.mozilla.Thunderbird
```

An update stays on the branch the object was installed from. It does not automatically switch a `stable` application to `beta`, for example.

To prevent an object from being updated:

```bash
flatpak mask org.mozilla.Thunderbird
```

To allow updates again:

```bash
flatpak mask --remove org.mozilla.Thunderbird
```

### Uninstall applications and runtimes

```bash
flatpak uninstall org.mozilla.Thunderbird
```

Uninstalling an application normally leaves its user data in `~/.var/app`. To remove that data too:

```bash
flatpak uninstall --delete-data org.mozilla.Thunderbird
```

A runtime cannot normally be removed while an installed application depends on it. Remove the dependent application first. Flatpak has a force option, but forcing runtime removal can break applications that still need it.

## 7.6 Summary

- A remote is a Flatpak software source.
- An application runs in a sandbox and may use a shared runtime.
- Use `flatpak remotes` and `flatpak remote-ls` to inspect sources and their contents.
- Use `flatpak search`, `install`, `list`, `info`, `update`, and `uninstall` to manage applications.
- Branches identify different versions, such as `stable` and `beta`; updates stay on the installed branch.
- Uninstalling an app may leave its data in `~/.var/app`.
- Red Hat does not support applications from third-party remotes such as Flathub.
