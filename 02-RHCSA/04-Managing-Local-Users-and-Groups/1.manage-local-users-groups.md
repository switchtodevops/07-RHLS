# Managing Local Users and Groups

## 4.1 Linux users and groups

Linux uses users and groups to control who owns files and which processes can access them. Each user has a numeric UID, and each group has a numeric GID.

### Three types of users

- **Root:** the superuser, with UID 0 and full administrative access.
- **System users:** run services and background processes; usually aren’t used for interactive login.
- **Regular users:** used for people’s day-to-day work and have limited access.

Useful commands:

```bash
id                 # your UID, primary GID, groups
id username        # another user's IDs and groups
ls -l file         # file owner and group
ls -ld directory   # directory owner and group
ps awwu            # processes associated with users
```

### Account information files

`/etc/passwd` contains one line per local user, with seven colon-separated fields:

```text
username:x:UID:GID:comment:home_directory:login_shell
```

For example:

```text
vinod:x:1000:1000:Vinod M V:/home/vinod:/bin/bash
```

The `x` indicates that the password hash is stored in `/etc/shadow`, not in this publicly readable file. A shell such as `/sbin/nologin` prevents interactive shell login.

`/etc/group` contains local group information, with four colon-separated fields:

```text
group_name:x:GID:supplementary_members
```

### Primary and supplementary groups

Every user has one primary group. New files normally get that group as their group owner. A user can also belong to multiple supplementary groups; those groups can grant access to files and resources.

Check a user’s groups with:

```bash
id username
```

## 4.3 Gaining superuser access

Use root privileges only when a task needs them. Working as root all the time increases the impact of mistakes.

### `su` and `su -`

```bash
su - username
```

Switches to another account and starts a login shell using that user’s environment. The command asks for the target user’s password.

```bash
su -
```

Switches to root. If no username is given, `su` assumes root. The `-` starts a login shell and loads the target user’s environment; administrators generally use this form when switching accounts.

### `sudo`

`sudo` runs an allowed command with elevated privileges. Usually, it asks for your own password, not root’s.

```bash
sudo command
sudo -i    # interactive root login shell
sudo -s    # root shell without login initialization
sudo -k    # clear cached credentials
```

The default `sudo` credential cache lasts five minutes. Sudo also logs commands, usually in `/var/log/secure`.

On RHEL 10, the root account has no valid password by default, so direct root login or `su -` may not work unless an administrator sets a root password. Sudo is commonly used instead.

### Sudo configuration

Use `visudo` to edit and validate the main sudoers file. RHEL also reads configuration files in `/etc/sudoers.d/`.

Example rule granting a group full sudo access:

```text
%wheel ALL=(ALL:ALL) ALL
```

- `%wheel` means the rule applies to the `wheel` group.
- `ALL=(ALL:ALL)` allows commands to run as any user and group.
- The final `ALL` allows any command.

A rule for one user omits the `%`:

```text
vinod ALL=(ALL) ALL
```

A `NOPASSWD` rule allows commands without a password, so grant it carefully.

## 4.5 Managing local user accounts

Create and manage local accounts as root or with `sudo`.

### Create a user

```bash
useradd username
passwd username
```

`useradd` reads defaults from `/etc/login.defs`, adds account records, creates `/home/username`, and copies default files from `/etc/skel`. The account still needs a password before the user can log in.

By default, regular users receive the first available UID starting at 1000 or higher.

### Modify a user

Common `usermod` options:

| Option | Purpose |
| --- | --- |
| `-c COMMENT` | Set the comment or description field |
| `-d HOME` | Set the home directory |
| `-m` | Move existing home contents; use with `-d` |
| `-g GROUP` | Change primary group |
| `-G GROUPS` | Set supplementary groups |
| `-aG GROUP` | Add a supplementary group while keeping existing memberships |
| `-s SHELL` | Set the login shell |
| `-L` / `-U` | Lock / unlock the account |

Exam trap: `usermod -G group username` replaces the user’s supplementary-group list. Use `-aG` when the task says to add a group.

```bash
usermod -aG wheel username
```

### Delete a user

```bash
userdel username       # removes account, leaves home directory
userdel -r username    # removes account and home directory
```

If you delete an account but leave its files, they remain owned by the old numeric UID. Reusing that UID can give a new account ownership of the old files. Check the consequences before removing accounts or reusing UIDs.

## 4.7 Managing local group accounts

### Create, modify, and delete groups

```bash
groupadd developers
groupadd -g 35000 consultants
groupadd -r servicegroup
```

`-g` sets a specific GID. `-r` creates a system group using the system GID range.

```bash
groupmod -n newname oldname     # rename a group
groupmod -g 36000 groupname     # change its GID
groupdel groupname              # delete a group
```

A group cannot be deleted while it is a user’s primary group. Before deleting a group, consider what files it owns.

### Change group membership

Change the primary group:

```bash
usermod -g developers username
```

Add a supplementary group without replacing existing memberships:

```bash
usermod -aG developers username
```

A user’s primary group affects the group ownership of newly created files. To temporarily use one of your supplementary groups as the current primary group in a shell:

```bash
newgrp developers
```

This affects that shell session; logging in again restores the user’s default primary group.

## 4.9 Managing user passwords

### Password hashes and `/etc/shadow`

Password hashes are stored in `/etc/shadow`, which only root can read. A password is not stored as plain text. The hash includes the algorithm, a random salt, and the resulting hash. During login, the system hashes the entered password with the stored salt and checks whether it matches.

RHEL 10 uses yescrypt by default for new and updated local passwords. Older supported hashes may still appear in `/etc/shadow`.

The shadow entry also stores password-aging and account-expiration information, including:

- Last password-change date.
- Minimum and maximum password age.
- Warning days before password expiry.
- Inactivity period after expiry.
- Account expiration date.

### Password aging with `chage`

```bash
chage -m 0 -M 90 -W 7 -I 14 username
```

This sets a minimum age of 0 days, maximum age of 90 days, a 7-day warning, and a 14-day inactive period after password expiry.

Other useful options:

```bash
chage -l username             # list aging settings
chage -E 2026-12-31 username  # set account expiration date
chage -d 0 username           # require password change at next login
```

Defaults in `/etc/login.defs`, such as `PASS_MAX_DAYS`, apply to new accounts. Use `chage` to change aging policy for an existing user.

### Locking accounts and disabling shell login

```bash
usermod -L username    # lock
usermod -U username    # unlock
```

Locking prevents password authentication. You can also set an account’s expiration date with `usermod -e`.

To prevent interactive shell login:

```bash
usermod -s /sbin/nologin username
```

`/sbin/nologin` blocks shell access, but it does not automatically block every form of access through services such as mail or file-transfer applications.

## 4.11 Lab: Manage local users and groups

The lab combines the chapter skills: set a default password-aging policy, create a group, grant that group sudo access through `/etc/sudoers.d/`, create users with supplementary group membership, set passwords and account-expiration dates, and force a password change at first login.

The key command patterns from the lab are:

```bash
useradd -G groupname username
chage -E YYYY-MM-DD username
chage -M days username
chage -d 0 username
```

For a group rule in `/etc/sudoers.d/`, the group name starts with `%`. Validate sudo configuration carefully; syntax mistakes can prevent intended sudo access.

## 4.12 Summary

Keep these distinctions clear:

- UID/GID are the numeric identities behind user and group names.
- A user has one primary group and may have several supplementary groups.
- Use `sudo` for authorized administrative commands; use `su -` to switch to another user’s login environment.
- Use `useradd`, `usermod`, and `userdel` for user accounts; use `groupadd`, `groupmod`, and `groupdel` for groups.
- Use `-aG` to add supplementary groups without replacing existing memberships.
- Use `chage` for password aging and expiration settings.
- A locked account, an expired account, and a `/sbin/nologin` shell are different controls.
